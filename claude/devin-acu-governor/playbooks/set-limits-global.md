# Playbook: set-limits-global (Seed org-level caps for uncapped orgs, by Borrowing)

Give an enforceable **org-level Local Agent limit** to billing organizations that currently have **no explicit org cap** (their `local_agent.cycle_acu_limit` is unset), and fund those new caps **zero-sum** by Borrowing cap headroom from orgs that already have explicit caps and the highest safe surplus. Σ explicit org caps stays unchanged, so the enterprise never tips into overage. This is the org-level counterpart of `dag set-limits-new` (which seeds per-user caps): use it after adding a new billing org, or when some orgs still ride unlimited while others are capped. It is not `dag set limit global <acus>` — that command writes one explicit number deterministically; this one computes the numbers from live consumption and borrows to fund them.

Recipients = orgs with no explicit org-level cap. Donors = orgs with an explicit cap, ranked highest **projected** safe surplus first, lowest consumption as tie-breaker. Recipients are never donors; donors are never re-capped upward. The borrowable budget is prorated evenly across recipient orgs (`floor(consumed_i) + min(share, max_headroom)`); the default plan passes `"max_headroom": 250`, a value between 250 and 500 may be passed only when the user explicitly requests it in this session, and above 500 is never valid — the jq built-in default of 500 is the backstop clamp (hard rule 11).

## Steps

1. **Cycle dates.** GET `/v3/enterprise/consumption/cycles`. Current cycle = item with `after <= now < before`. Convert epochs to dates for display.
2. **Org roster.** GET `/v3/enterprise/organizations` — `items[]` of `{org_id, name, max_session_acu_limit, max_cycle_acu_limit}`. This is the full candidate set; there is no activity filter at org level (every billing org is eligible).
3. **Per-org consumption.** For each org, GET `/v3/enterprise/consumption/daily/organizations/{org_id}` with the cycle's `time_after`/`time_before`; take each `total_acus` as the org's current-cycle consumed. Also derive each org's `run_rate` (last-7-day average ACUs/day) from the same endpoint with `time_after = now − 7d`.
4. **Read live current org limits — classify capped vs uncapped.** For every org, GET `/v3beta1/enterprise/organizations/{org_id}/consumption/acu-limits`. The GET returns an explicit setting only. Partition:
   - **Recipients** = orgs whose `local_agent.cycle_acu_limit` is unset (no explicit org cap).
   - **Donors** = orgs whose `local_agent.cycle_acu_limit` is set.
   If every org already has an explicit cap, report "all orgs already have explicit org-level caps — nothing to seed" and stop. If N(orgs) = 1 there is nothing to borrow across — point at `dag set limit global <acus>` and stop.
5. **Confirm recipient scope — not write authorization.** Present the uncapped org table (org_id, name, consumed, run_rate) and the capped donor org summary (org_id, name, cap, consumed, headroom). Ask the user to confirm the recipient org list or name exclusions, and stop for that reply. Scope confirmation does not authorize any PATCH — the separate `CONFIRM DAG WRITE` gate still applies.
6. **Plan the borrow.** Build the `borrow_caps_jq` input, mapping org rows into the program's row shape (`email` ← org name, `user_id` ← org_id, `member: true`, `active: true` — the program's member/activity filters are user-level concepts and every org passes them):
   ```json
   {"donor_buffer": 0.10, "max_headroom": 250, "days_left": <days left in cycle>,
    "recipients": [{"email": <org name>, "user_id": <org_id>, "consumed": ..., "member": true, "active": true}, ...],
    "donors":     [{"email": <org name>, "user_id": <org_id>, "cap": ..., "consumed": ..., "run_rate": <last-7d ACUs/day>, "member": true, "active": true}, ...]}
   ```
   Run `jq -f <borrow_caps_jq>`. A donor org's `run_rate` raises its protected floor to projected end-of-cycle consumption + buffer (`ceil((consumed + run_rate × days_left) × 1.1)`); no donor org is cut below its floor, and no org cap is ever set below that org's own current consumption. Use `recipients_capped`, `recipients_skipped`, and `donor_takes` exactly as returned; report every skipped org unchanged and uncapped — no overage is ever created.
   **No-donor fallback:** if there are zero capped donor orgs, zero-sum borrowing is impossible. Offer exactly one alternative in the preview: prorate `DAG_MONTHLY_ACU_POOL` across all orgs proportionally to current-cycle consumption (minimum `ceil(consumed + max_headroom)` each, Σ org caps ≤ pool), state the total exposure this creates, and require the same `CONFIRM DAG WRITE` before writing.
7. **Preview and confirm.** Show two tables — **Recipient orgs (new caps):** org_id, name, consumed, new `cycle_acu_limit`, headroom; **Donor orgs (borrowed from):** org_id, name, cap_before → cap_after, given — plus `mode`, `borrowed`, and `sum_before == sum_after` (prove zero-sum). If `mode` is `partial`, do not write: list `recipients_skipped` and ask the user to choose exactly one keyword — `PARTIAL`, `CHANGE DONORS`, or `CANCEL`. Note that org caps and per-user caps are independent layers: an org cap bounds the whole org regardless of per-user overrides; flag any org whose Σ per-user caps exceeds its proposed org cap. Print UI instruction: `app.devin.ai > Enterprise Settings > Consumption`. Then stop; write only after the user sends `CONFIRM DAG WRITE` (hard rule 2).
8. **PATCH changed orgs.** For each `recipients_capped` org **and** each `donor_takes` org, PATCH `/v3beta1/enterprise/organizations/{org_id}/consumption/acu-limits` with body `{"local_agent":{"cycle_acu_limit":<cap>}}`. Never write a `recipients_skipped` org.
9. **Live verify.** GET each changed org limit after PATCH. Confirm `local_agent.cycle_acu_limit` equals the planned value for every org. On the first failed PATCH or verification GET, quote the exact response body and perform no further PATCH or ledger update in this run; report applied, failed, and unattempted rows, then offer a new read-and-preview run for only that subset.
10. **Update ledger.** Refresh org-level entries in the ledger under an `orgs` key with `{org_id, name, cap, consumed}` and an updated timestamp, separate from the per-user entries. Re-read the file and show changed entries. With zero-sum borrowing, Σ org caps is unchanged vs before.
11. **Report.** List newly-capped orgs, donor orgs and what each gave, any orgs left uncapped, and any org whose Σ per-user caps exceeds its new org cap. Point to `dag set limit global <acus> [org]` for explicit one-number writes and `dag set-limits-new` for the per-user layer.
